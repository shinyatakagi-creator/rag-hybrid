# Failure analysis: c009, c010, c002

Diagnosis of the three conceptual questions the baseline misses most. The golden set is not changed. Data: `failure_analysis_data.json` (from `python -m eval.failure_analysis`, no API calls). "Rank" = chunk rank in the retriever's 200-chunk window; "first rank" = rank of the first expected doc after dedupe (baseline). The "answer chunk" is the chunk containing the sentence I found by reading the expected page. The explanations are my reading of this evidence, not tested hypotheses.

## c009: "Our cluster grows and shrinks its node count by itself, but the count is often wrong for the load. How can bad CPU and memory requests on Pods cause that?"

Expected: `concepts/cluster-administration/node-autoscaling`. First rank in the baseline: bm25 not returned (both chunkers), dense 29 (fixed) / 28 (heading), hybrid 50 / 43.

- **Answer chunk.** Heading chunker, 230 tokens, section "Vertical workload autoscaling": "If the requests of a given Pod are too low, provisioning a new Node for it might not help the Pod actually run. If the requests of a given Pod are too high, it might incorrectly prevent consolidating its Node." The fixed chunker puts the same sentences in a 390-token chunk headed only "Node Autoscaling".
- **BM25.** Answer chunk is outside the 200-chunk window for both chunkers. The query words that match it are generic: `node`, `pod`, `request`, `cluster` (plus `it`, `can`, `and` via the title/heading fields). The page's own vocabulary (`provisioning`, `consolidating`, `autoscaling`) is absent from the question. What BM25 ranks first (heading): "Calculate the total reserved resources" on `node-overprovisioning`, then user-namespaces and cpu-management-policies, all mentioning nodes, pods and resources many times.
- **Dense.** Answer chunk ranks 59 (heading) and 73 (fixed); the page's best chunk is rank 56 / 73. Top results are `assign-cpu-resource` ("Motivation for CPU requests and limits") and `manage-resources-containers` (scheduling with requests): the question's strongest topic is "CPU and memory requests", and those pages are about exactly that, while the autoscaling link is one clause.
- **Reading.** The question's subject is requests; the page's subject is node autoscaling, and the requests sentence is a short caution inside a section about vertical autoscaling. Both retrievers follow the question's dominant topic to the dedicated requests pages. The question never says "autoscaler" or "scale up/down" in the words the page uses, so lexical matching has nothing specific to latch onto, and dense similarity is spent on the CPU/memory phrasing. This is a hard, plausible user question, not a golden-set error: the page does answer it, in one sentence.

## c010: "We pushed a new version of an agent that runs on every node, but on some nodes the new Pods can't start because those nodes are full. What should I do?"

Expected: `tasks/manage-daemon/update-daemon-set`. First rank: bm25 23 (fixed) / 4 (heading), dense not returned (fixed) / 59 (heading), hybrid 55 / 8.

- **Answer chunk.** Heading chunker, 342 tokens, "DaemonSet rolling update is stuck": "The rollout is stuck because new DaemonSet pods can't be scheduled on at least one node... delete some non-DaemonSet pods from the node to make room for new DaemonSet pods." Fixed chunker: 403 tokens headed "Perform a Rolling Update on a DaemonSet".
- **BM25.** Answer chunk rank 6 (heading), 72 (fixed). It matches the question's `can't`, `new`, `node`, `pod`, `run`, `some`, `those` (plus stopword-ish `a`, `becaus`). This is the one case where BM25 does best: the question and the page share ordinary words ("can't", "new", "some", "nodes"). Ahead of it are three `pods-some-nodes` chunks ("Running Pods on Only Some Nodes"), whose title repeats "some nodes" and so wins the boosted title/heading fields.
- **Dense.** Answer chunk rank 132 (heading) and not in the window (fixed). The top three are all `manage-resources-containers` "My Pods are pending with event message `FailedScheduling`", a troubleshooting section about pods that cannot be scheduled because nodes lack resources. Semantically that is a close match to "Pods can't start because those nodes are full"; the question never says DaemonSet or rolling update, and "agent that runs on every node" is a paraphrase the embedding does not tie to DaemonSet strongly.
- **Reading.** The expected page answers a more specific situation (a DaemonSet rollout stuck on full nodes) than the question names. Dense retrieval finds the general "pending pod, node out of resources" page, which is a reasonable answer to the literal words, so this may be partly a case of a competing relevant page rather than a pure miss. BM25 wins because of incidental word overlap. Hybrid inherits dense's weaker rank (55 / 8).

## c002: "Checking live CPU and memory use per node fails, and the controller that grows and shrinks my workloads has stopped working too. What add-on supplies the numbers both rely on?"

Expected: `tasks/debug/debug-cluster/resource-usage-monitoring` and `tasks/debug/debug-cluster/resource-metrics-pipeline`. First rank: bm25 not returned (both), dense 8 (fixed) / 4 (heading), hybrid 19 / 11. (The question is the reworded version; the baseline ran on it.)

- **Answer chunks.** `resource-usage-monitoring`, heading chunk "Resource metrics pipeline" (303 tokens): "metrics-server discovers all nodes on the cluster and queries each node's kubelet for CPU and memory usage." `resource-metrics-pipeline`, "Resource metrics pipeline" (339 tokens): "metrics-server: Cluster addon component that collects and aggregates resource metrics pulled from each kubelet."
- **BM25.** Neither page's chunks are in the 200-chunk window. The matching words are `cpu`, `memory`, `node`, `use`, `work` (and `workload`, `per` on the pipeline page), all very common in the corpus. The question names no component and avoids `metrics-server`, `kubectl top` and `autoscaler`. BM25's top results are `cpu-management-policies` chunks, which are dense with the words CPU and node.
- **Dense.** The `resource-usage-monitoring` answer chunk ranks 5 (heading) and 13 (fixed), a decent semantic hit; the `resource-metrics-pipeline` answer chunk ranks 174 (heading) and is not in the fixed window (the page's best chunk is 43 / 57). Top-1 for dense is the generated "List of Alpha Kubernetes Metrics" reference page, which is about metrics in general.
- **Reading.** The question hides the answer's vocabulary on purpose (no "metrics-server", no "kubectl top"), so lexical matching has only generic words. Dense retrieval partly bridges the gap for one of the two pages. Because the target is a component name that does not appear in the question, a retriever must infer "the thing that supplies per-node CPU/memory numbers to autoscaling and `top`", which needs the pipeline sentence, not generic metrics material. The second expected page (added after the page check) does not help in the baseline: its answer chunk ranks 174 or lower.

## Common pattern
All three are conceptual questions whose answer sits in a single sentence inside a longer section, and whose wording avoids the sentence's key nouns (autoscaling, DaemonSet, metrics-server). BM25 finds them only when ordinary words happen to overlap (c010). Dense retrieval finds the question's dominant topic rather than the specific answer sentence (requests pages for c009, a general pending-pod page for c010, general metrics pages for c002). The retrieval ranks are not evidence of a golden-set error in these three; I made no change to it.
